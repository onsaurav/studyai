D01

LLM Internals

≈ 41 hrs

What's happening inside the models you call every day. Stop treating GPT-4o as a black box.

PSkill / TermHrsShort descriptionTrack
🔴Tokenization (BPE, WordPiece, SentencePiece)2Why tokens, not words. Cost & context-window implications.
🔴Embeddings4Dense vectors, semantic similarity, embedding models ≠ LLMs.
🔴Attention mechanism (self-attention, Q/K/V)6The core of transformers. O(n²) scaling — why context costs explode.
🔴Transformer architecture8Encoder-only / decoder-only / encoder-decoder. Know which family each model is.
🔴Context window & KV cache2Why limited, what happens at overflow, memory cost of long context.
🔴Sampling: temperature, top-p, top-k2How models choose next token. When to use each setting.
🔴Pretraining vs Fine-tuning vs Instruction tuning4What each is, cost order of magnitude, when each makes business sense.
🔴Hallucination — mechanical cause3Not "the model lies." Probabilistic next-token generation under uncertainty. Detection & mitigation.
🟡RLHF / DPO3Conceptual only. How models get aligned. You won't train this, you must explain it.
🟡Quantization (INT8 / INT4 / GGUF)3How OS models shrink for laptop/edge inference. Quality vs size trade-off.
🟡LoRA / QLoRA4Parameter-efficient fine-tuning. You will actually do this in Q2 of Year 1.
🟢Mixture of Experts (MoE)1Why GPT-4 and DeepSeek route tokens through experts. Awareness only.
🟢Speculative decoding1Inference speed trick. Small "draft" model proposes, large model verifies.
🟢Flash Attention1Memory-efficient attention kernel. Know it exists, know it matters for long context.
D02

Retrieval & RAG

≈ 31 hrs

Most "broken AI" is actually broken retrieval. This is where your current production bots live or die.

PSkill / TermHrsShort descriptionTrack
🔴Cosine similarity2Angle between vectors, not distance. The math behind embedding search.
🔴Vector DB / index structures (HNSW, IVF)4What's actually happening under the hood when "vector search" runs.
🔴BM25 / lexical search2Classic keyword scoring. Still beats vectors on exact-term enterprise queries.
🔴Hybrid search + RRF3Dense + sparse fused via Reciprocal Rank Fusion. Production default.
🔴Chunking strategies4Fixed-size, semantic, recursive, parent-document. Where most RAG silently fails.
🔴Reranking (cross-encoders)3Two-stage retrieval: recall many, rerank top. Almost always beats one-stage.
🟡HyDE (Hypothetical Doc Embeddings)2LLM hallucinates an "ideal answer" first, then searches with that. Helps on vague queries.
🟡Multi-query retrieval2Generate N reformulations of the user question, retrieve for each, merge.
🟡Contextual retrieval (Anthropic)2Prepend an LLM-generated context blurb to each chunk before embedding. Read the original post.
🟡Query rewriting / expansion2Often higher-impact than fancy embeddings. Cheap to add.
🟢GraphRAG2Microsoft approach — retrieve from a knowledge graph. Powerful but expensive.
🟢ColBERT / late interaction1Token-level matching instead of doc-level embeddings. Awareness only.

Agents & Tool Use

≈ 33 hrs

Production agents — not demos. The skill that puts you ahead of 95% of "AI engineers."

PSkill / TermHrsShort descriptionTrack
🔴Function calling / tool use4Schema design, error handling, parallel calls — beyond the API tutorial.
🔴ReAct pattern (Reason + Act)3Foundation of most agents. Build one without a framework once.
🔴Agent memory: short / long / episodic4Sliding window vs summarization vs vector memory. How to actually implement.
🔴Multi-agent orchestration patterns6Sequential, hierarchical, collaborative. When each fits.
🔴Model Context Protocol (MCP)3Anthropic's open standard for tool/context plumbing. Becoming the default.
🟡Plan-and-Execute pattern2Plan all steps up front, then execute. Alternative to ReAct's loop.
🟡Reflection / self-critique2Agent reviews its own output and revises. Cheap quality lift.
🟡Semantic Kernel internals4You use it daily — master Kernel, Plugins, Planners, Memory deeply.
🟡LangGraph4State-machine approach to agents. Worth knowing even if you stay in SK.
🟢AutoGen / CrewAI2Multi-agent frameworks. Awareness — know when someone proposes them.
D04

Evaluation & LLMOps

≈ 35 hrs — your strongest moat

Go deeper here than most engineers do. This is the discipline that separates a demo from a system.

PSkill / TermHrsShort descriptionTrack
🔴LLM-as-judge4Use one LLM to score another. Setup, biases (position, verbosity, self-preference), when it fails.
🔴Golden datasets330–50 hand-crafted question→ideal-answer pairs. Foundation of every honest eval.
🔴Regression testing for LLMs3CI that re-runs evals on every prompt/model change. Catches silent breakage.
🔴RAG eval metrics — Ragas4Faithfulness, answer relevance, context precision, context recall. Install and run.
🔴Observability for LLM apps4Tracing, spans, debugging non-deterministic systems. Langfuse / Phoenix / Arize.
🔴Cost tracking & optimization3Per-request cost, per-user, per-feature. Model routing, caching.
🔴Latency optimization3Streaming, parallel tool calls, prompt caching. UX is dominated by latency.
🟡Prompt versioning2Git for prompts. A/B testing in production.
🟡Guardrails3Content filtering, PII detection, jailbreak detection. Azure Content Safety + Prompt Shields.
🟡Semantic caching2Cache at meaning-level, not exact-match. Big cost savings on repetitive queries.
🟡Prompt caching1Provider feature (Anthropic, OpenAI). Cache long system prompts cheaply.
🟢Shadow deployment for LLMs1Run new model alongside old, compare silently. Awareness.
🟢Canary releases for prompts1Roll new prompt to 1% → 10% → 100%. Awareness.
D05

Math Foundations (bounded — stop here)

≈ 42 hrs

Just enough to read papers, debug training, work as a peer with data scientists. No measure theory. No proofs. No theoretical ML.

PSkill / TermHrsShort descriptionTrack
🔴Vectors, matrices, matrix multiplication8Operationally fluent in NumPy. Geometric intuition matters more than proofs.
🔴Dot product, norms, projections4The math under cosine similarity, which is the math under embedding search.
🔴Gradient, partial derivatives, chain rule6Enough to derive backprop by hand once. Then move on.
🔴Probability — distributions, Bayes, expectation6Applied level. Normal, Bernoulli, binomial, categorical. Bayes' theorem with concrete problems.
🟡Eigenvalues / eigenvectors / SVD4SVD is the math behind PCA and behind LoRA. Conceptual + np.linalg practice.
🟡Gradient descent (SGD, Adam)4Understand the updates. Don't derive Adam from scratch.
🟡MLE / MAP3Foundation for understanding loss functions. Why cross-entropy is "the" classification loss.
🟡Hypothesis testing, p-values, confidence intervals4For A/B testing AI systems and evaluating eval results honestly.
🟢Convexity1Why some losses guarantee global optima and others don't. Awareness.
🟢Information theory (entropy, cross-entropy, KL)2Cross-entropy IS the LLM loss function. Read Olah's "Visual Information Theory."
D06

Classical ML

≈ 37 hrs

Do not skip. Trees still beat neural nets on tabular data, and "data leakage" is the #1 reason great offline models fail in production.

PSkill / TermHrsShort descriptionTrack
🔴Linear & logistic regression + L1/L24From scratch in NumPy once. Including regularization intuition.
🔴Decision trees, Random Forests, XGBoost / LightGBM6Still wins Kaggle on tabular data. Know hyperparameters: learning_rate, max_depth, n_estimators.
🔴Train / val / test splits + cross-validation3Done properly. K-fold, stratified, time-series CV.
🔴Bias–variance trade-off2The conceptual frame for under/overfitting. Fundamental.
🔴Eval metrics: precision, recall, F1, AUC, calibration4When each is appropriate. PR vs ROC curves. Why probabilities from boosters need calibration.
🔴Feature engineering6Hands-on across multiple projects. Encoding, transformations, datetime, text features.
🔴Data leakage2Target leakage, train-test contamination, temporal leakage. #1 cause of production failure.
🟡k-means & hierarchical clustering3Unsupervised baseline. Limits and assumptions.
🟡PCA, t-SNE, UMAP3Dimensionality reduction & visualization. UMAP is the modern default.
🟡SVM2Conceptual only. Kernel trick. Historical importance.
🟡Naive Bayes, k-NN2Simple baselines. Still useful in some text/anomaly tasks.
🟡Imbalanced data: SMOTE, class weights, threshold tuning3Fraud / medical / churn — most real problems are imbalanced.
🟢Time-series basics2Upgrades to 🔴 if your vertical is forecasting. ARIMA, Prophet, lagged features.

Deep Learning

≈ 42 hrs

PyTorch won. Implement backprop by hand once, then live in the framework.

PSkill / TermHrsShort descriptionTrack
🔴Neural network fundamentals6Forward + backward pass by hand once. 2-layer NN in pure NumPy. Pays off forever.
🔴PyTorch (tensors, autograd, nn.Module, training loops)10Fluent. Tensors, autograd, DataLoader, debugging gradients.
🔴Activation functions2ReLU, GELU, SiLU. Why dead ReLUs happen. Why GELU dominates in transformers.
🔴Loss functions3Cross-entropy, MSE, focal loss. When each is appropriate.
🔴Optimizers + LR schedules3SGD, Adam, AdamW. Cosine and warmup schedules.
🔴Regularization3Dropout, batch norm, layer norm, weight decay. Why each works.
🟡CNNs4Foundation even outside vision. Convolutions, pooling, receptive fields.
🟡Hugging Face Transformers library8You'll use this heavily for fine-tuning and inference.
🟡PEFT library (LoRA & friends)4HF's parameter-efficient fine-tuning. Hands-on for your Q2 capstone.
🟢RNNs / LSTMs2Mostly historical. Useful context for why transformers won.
🟢GANs1Awareness only. Largely supplanted by diffusion for generation.
🟢Diffusion models2Upgrades to 🔴 if image-gen becomes your vertical.
